# PM Cursor MVP — единый контекст

Этот файл — главная точка входа в контекст проекта. Если ты (человек или ИИ‑агент) собираешься что‑то менять в коде, **сначала прочитай DOCS.md и CHANGELOG.md.**

---

## 0) TL;DR проекта (до 10 строк)
- **Что это:** маленький MVP‑инструмент для продакт/дизайн‑работы. Загружаем макеты, описываем фичу, получаем структурированный ответ от дизайнера‑LLM; плюс One-doc RAG — один документ о продукте, ответы на вопросы только по нему.
- **Для кого:** продуктовые менеджеры, дизайнеры и разработчики, которым нужно быстро формализовать дизайн‑задачу по уже существующим макетам и задавать вопросы по документу о продукте.
- **Главная ценность:** быстрый дизайн‑бриф из LLM по макетам; RAG: ответы на вопросы строго по загруженному документу (чанки + эмбеддинги + retrieval).
- **Что уже работает:** загрузка 1–10 изображений, текстовый запрос, `/api/design`; **User Segments** (`/user-segments`) — таблица сегментов внизу; **One-doc RAG** (`/kb`, `/ask`): чанки, эмбеддинги, ответы по контексту; **Backlog** (`/backlog`): карточки со статусами (Backlog / To Do / In Progress / Done), добавление/перемещение/удаление, кнопка Generate по документу из `/kb` (промпт в `BACKLOG_GENERATE_PROMPT.md`).
- **Где UI:** `/` (Design Brief), `/user-segments`, `/kb`, `/ask`, `/backlog`. App Router, Next.js 16, React 19.
- **Где API:** `POST /api/design`, `POST /api/user-segments`; RAG: `POST /api/kb/set`, `GET /api/kb/get`, `POST /api/kb/clear`, `POST /api/ask`; Backlog: `POST /api/backlog/generate` (документ из storage + промпт из файла).
- **Где живёт прод:** Vercel. Данные RAG: при наличии KV_REST_API_* — Vercel KV; иначе in-memory (на проде без KV документ не персистится между запросами).
- **Что НЕ делаем:** нет полноценной истории чатов, нет аутентификации; RAG — один общий документ без привязки к пользователю.
- **Версия сейчас:** см. последнюю запись в `CHANGELOG.md` (на момент редактирования — `v0.6` от 2026‑02‑17).

## 1) Как запускать (локально / прод)

### 1.1. Локально (dev)
```bash
npm install
npm run dev
```

- Открыть `http://localhost:3000`.
- Изменения в `app/page.tsx` и `app/api/design/route.ts` подхватываются hot‑reload.
- Для корректной работы API нужен `.env.local` (см. ниже).

### 1.2. Локально (prod‑режим)
```bash
npm install
npm run build
npm run start
# по умолчанию: http://localhost:3000
```

Если порт 3000 занят, останови предыдущий `node`:
```bash
lsof -i :3000
kill <PID>
```

### 1.3. Прод (Vercel)
- Репозиторий подключен к Vercel (см. панель проекта).
- **Базовый flow:**
  1. Коммиты в `main` → авто‑деплой.
  2. Если нужен ручной релиз — создать ветку, PR, смёржить в `main`.
- **Обязательные env vars в Vercel:**
  - `LLM_API_KEY` — ключ к выбранному LLM‑провайдеру.
  - `LLM_BASE_URL` — base URL совместимого с OpenAI API (`https://api.openai.com/v1` или свой шлюз).
  - `LLM_MODEL` — идентификатор модели (по умолчанию `"gpt-4o-mini"`).
- **Для One-doc RAG:**
  - `EMBEDDING_MODEL` — модель для эмбеддингов (по умолчанию `text-embedding-3-small`).
  - `KV_REST_API_URL`, `KV_REST_API_TOKEN` — опционально; при наличии документ/чанки/эмбеддинги хранятся в Vercel KV; без них — in-memory (на проде не персистится).
- `.env.local` используется только локально и **никогда не коммитится**.

### 1.4. Основные урлы
- `/` — основной UI (Design Brief: загрузка макетов, форма запроса, панель чатов, результат).
- `/user-segments` — UI сегментации: описание продукта, кнопка генерации, блок сегментов внизу (таблица в стиле Notion).
- `/kb` — База знаний: загрузка одного документа (title + content), кнопки «Сохранить документ» и «Удалить документ».
- `/ask` — Спросить: вопрос по документу, ответ и блок «использованный контекст» (чанки с score).
- `/backlog` — Backlog: колонки Backlog / To Do / In Progress / Done, карточки фич, добавление/перемещение/удаление, кнопка Generate (анализ документа из `/kb`, промпт — `BACKLOG_GENERATE_PROMPT.md`). Карточки в `localStorage`.
- `POST /api/design` — эндпоинт: `featureRequest` + массив `images` (dataURL).
- `POST /api/user-segments` — эндпоинт: `context` (описание продукта), промпт из `USER_SEGMENTS_PROMPT.md`.
- `POST /api/kb/set` — тело `{ title, content }`: чанки, эмбеддинги, сохранение в хранилище.
- `GET /api/kb/get` — текущий документ и мета (chunksCount).
- `POST /api/kb/clear` — удаление документа, чанков, эмбеддингов.
- `POST /api/ask` — тело `{ question }`: retrieval (topK чанков), ответ LLM по контексту.
- `POST /api/backlog/generate` — без тела: читает документ из storage (База знаний), системный промпт из `BACKLOG_GENERATE_PROMPT.md`, возвращает `{ ok, features: [{ title, description }] }`. Требуется предварительно сохранить документ на `/kb`.

## 2) Архитектура (коротко)

### 2.1. Frontend (App Router)
- `app/layout.tsx`
  - Подключает шрифты Geist.
  - Подключает глобальные стили `globals.css`.
- `app/page.tsx` (Design Brief)
  - `"use client"`.
  - Стейт: `files`, `featureRequest`, `result`, `error`, `isDesigning`, `chats`, `activeChatId`, `chatCounter`, `theme`.
  - UI: левая панель Workspace/чаты, основная панель (макеты, textarea, кнопка «Спроектировать», блоки «Результат» и «Ошибки»).
- `app/user-segments/page.tsx` (User Segments)
  - `"use client"`.
  - Стейт: `input`, `result`, `error`, `isLoading`, `chats`, `activeChatId`, `chatCounter`, `theme`.
  - Ответ LLM парсится на фронте (`parseSegmentsFromMarkdown`): из markdown‑таблицы извлекаются сегменты (название, описание, JTBD, %).
  - UI: левая панель чатов, форма (описание продукта, кнопка «Сгенерировать сегменты», поле ввода чата), справа блок «Ошибки»; **внизу страницы** — блок «Сегменты пользователей»: при успешном парсинге — таблица в стиле Notion (колонки Сегмент, Описание, Работы (JTBD), % пользователей), иначе сырой текст.

### 2.2. Backend (`/api/design`)
- Файл: `app/api/design/route.ts`.
- Ожидаемый `POST`‑body:
  ```json
  {
    "featureRequest": "строка, обязательна",
    "images": ["data:image/png;base64,..."]
  }
  ```
- Валидация:
  - `featureRequest` обязателен и триммится.
  - `images` — обязательный непустой массив строк.
- Конфигурация LLM:
  - Используются `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` из `process.env`.
  - `LLM_MODEL` по умолчанию `"gpt-4o-mini"`, если не задан.
- Вызов LLM:
  - `POST ${LLM_BASE_URL}/chat/completions` с телом `{ model, messages }` в OpenAI‑совместимом формате.
  - В `messages`:
    - `system`: инструкция продуктовому дизайнеру.
    - `user`: текст + массив `image_url`.
- Ответ:
  - `200 { ok: true, result }` при успехе.
  - При ошибке LLM → проброс текста ошибки и статуса.
  - При непредвиденной ошибке → `500 { ok: false, error: "Непредвиденная ошибка на сервере." }`.

### 2.3. Backend (One-doc RAG)
- **Хранилище** (`lib/storage.ts`): при наличии `KV_REST_API_URL` и `KV_REST_API_TOKEN` — Vercel KV (ключи `kb:doc`, `kb:chunks`, `kb:embeddings`); иначе in-memory объект.
- **Сохранение документа** (`app/api/kb/set/route.ts`): body `{ title, content }` → чанки (`lib/chunk.ts`, ~1000 символов, overlap 150) → для каждого чанка вызов `lib/llm.ts` `embeddings()` → сохранение doc, chunks, embeddings через storage.
- **Получение документа** (`app/api/kb/get/route.ts`): возврат doc и meta (chunksCount).
- **Очистка** (`app/api/kb/clear/route.ts`): удаление трёх ключей в storage.
- **Вопрос** (`app/api/ask/route.ts`): body `{ question }` → эмбеддинг вопроса через `embeddings()` → косинусное сходство с сохранёнными эмбеддингами (`lib/cosine.ts`) → top 6 чанков → контекст + системный промпт («отвечай только по CONTEXT») + вопрос в `chat()` → ответ и список чанков с score.

### 2.4. Backend (Backlog Generate)
- **Генерация фич** (`app/api/backlog/generate/route.ts`): без body. Читает документ из `storage.getDoc()`; если нет — 400. Системный промпт из `BACKLOG_GENERATE_PROMPT.md` (кэш в памяти). User‑сообщение — название и содержание документа. Вызов `chat()` из `lib/llm.ts`. Парсинг JSON из ответа (`features: [{ title, description }]`), возврат клиенту. Карточки на фронте сохраняются в `localStorage` (страница `/backlog`).

### 2.5. Конфиг и стили
- `globals.css`:
  - Tailwind (`@import "tailwindcss"`).
  - CSS‑переменные `--background` / `--foreground`, маппинг на Tailwind‑тему.
  - Боди по умолчанию — белый фон, системный шрифт (Geist через css‑переменные).
- `tsconfig.json` — стандартный Next 16, пути `@/* -> ./*`.

## 3) “Глобальная инструкция для Cursor / ИИ‑агентов”

**Перед любым изменением:**
1. Прочитай `DOCS.md` и последние записи `CHANGELOG.md`.
2. Если задача связана с продом/ошибками — прочитай `RUNBOOK.md`.
3. Сформулируй в ответе пользователю план из 5–7 шагов.
4. Явно перечисли, какие файлы собираешься менять.

**После изменений:**
1. Обнови `CHANGELOG.md` (новая версия, пункты изменений).
2. Обнови `TODO.md` (Done/Next/Backlog).
3. Если затронут прод/деплой — дополни `RUNBOOK.md` (как воспроизвести и чинить).
4. Любые новые env‑переменные опиши в `DOCS.md` и `README.md`.

**Правила:**
- Не ломать текущий UI и основной сценарий: загрузка макетов → описание → кнопка → результат.
- По умолчанию **не добавляем новые зависимости**, если без них можно обойтись.
- Сохраняем понятные русские тексты ошибок/подсказок.
- Любая прод‑ошибка → добавить в раздел известных проблем/CHANGELOG.

## 4) Текущее состояние (state snapshot)

- **Версия:** см. последнюю запись в `CHANGELOG.md` (сейчас `v0.6`).
- **Последний деплой:** прод на Vercel, ветка `main` (URL — в настройках Vercel‑проекта).
- **Известные проблемы:**
  - Большие base64‑payload с изображениями могут не помещаться в лимиты Vercel/LLM‑провайдера.
  - Чаты и тема живут только в памяти клиента; при перезагрузке страницы сбрасываются.
  - RAG без KV на проде: документ/чанки/эмбеддинги in-memory не персистятся между запросами (нужен KV или другое хранилище).
  - Backlog: карточки только в `localStorage` (per‑browser, не общие между пользователями).
- **Следующие 3 задачи (рекомендуемые):**
  1. Сохранение истории чатов (минимум `localStorage`, дальше — backend/БД).
  2. Ограничение размера изображений и общего payload + дружелюбные ошибки в UI.
  3. На проде для RAG — подключить Vercel KV (или Supabase/другое хранилище) и описать в RUNBOOK.
