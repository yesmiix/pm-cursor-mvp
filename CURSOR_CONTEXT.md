1. Всегда сначала прочитай `DOCS.md` и последние записи в `CHANGELOG.md`.
2. Если задача связана с продом, деплоем или инцидентами — прочитай `RUNBOOK.md`.
3. В ответе пользователю:
   - коротко перескажи контекст задачи;
   - набросай план из 5–7 шагов;
   - явно перечисли файлы, которые собираешься менять.
4. При изменениях:
   - не ломай основной UX: загрузка макетов → описание → «Спроектировать» → результат;
   - не добавляй новые зависимости без необходимости и объяснения в `README.md`;
   - пиши тексты UI и ошибок по‑русски, кратко и понятно.
5. После изменений:
   - обнови `CHANGELOG.md` (новая версия + пункты изменений);
   - обнови `TODO.md` (Done/Next/Backlog);
   - при работе с продом/инцидентами дополни `RUNBOOK.md` (как воспроизводить и чинить).

Если нужно принять архитектурное решение или крупный рефакторинг — сначала опиши несколько вариантов в ответе пользователю, выбери один и только потом вноси изменения в код.
